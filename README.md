# petistat

Інфографіка формату A4 по **підписантах петицій до Кабінету Міністрів України**
([petition.kmu.gov.ua](https://petition.kmu.gov.ua)).

Вставляєте посилання на петицію, і програма:

1. визначає автора петиції;
2. знаходить **усі петиції цього автора** в публічному списку сайту;
3. завантажує підписантів кожної з них, а також еталонну вибірку великих петицій інших авторів;
4. рахує стать підписантів, частку ПІБ, записаних **КАПСОМ**, динаміку підписів і перетини аудиторій;
5. збирає 3-сторінковий звіт A4 у форматах HTML і PDF.

## Що в звіті

| Сторінка | Зміст |
|---|---|
| 1. Огляд | усі петиції автора: підписи, частка жінок, частка КАПСУ; загальні цифри |
| 2. Фокус | вибрана петиція: стать (точно та «лише за прізвищем»), підписи по днях і годинах, прогрес до 25 000, найчастіші імена |
| 3. КАПС | чому частину ПІБ записано великими літерами: докази, порівняння з еталоном, висновок |

## Встановлення

Потрібні Python ≥ 3.10 і (для PDF) Chromium або Google Chrome.

```bash
# з uv (рекомендовано)
uv sync

# або з pip
python -m venv .venv && . .venv/bin/activate
pip install -e .
```

## Запуск

### TUI (інтерактивно)

```bash
uv run petistat          # або просто: petistat (у активованому venv)
```

Програма запитає посилання на петицію (наприклад `https://petition.kmu.gov.ua/petitions/11247`
або просто `11247`) і спитає, чи оновлювати дані, чи робити PDF і яким **шрифтом** верстати звіт.
Потім покаже автора та список його петицій, після підтвердження завантажить дані й відкриє готовий
звіт у браузері. Останнє посилання та вибраний шрифт вона запам'ятовує (`data/state.json`).

### Одною командою

```bash
uv run petistat https://petition.kmu.gov.ua/petitions/11247
uv run petistat 11247 --open             # відкрити звіт після генерації
uv run petistat 11247 --refresh          # примусово оновити дані автора
uv run petistat 11247 --offline          # лише кеш, без мережі
uv run petistat 11247 --no-pdf           # тільки HTML
uv run petistat 11247 --baseline 20 --baseline-since 2026-01-01
python -m petistat 11247                 # те саме без entry point
```

| Опція | Типово | Опис |
|---|---|---|
| `--refresh` | — | ігнорувати свіжість кешу для даних автора |
| `--offline` | — | не звертатися до сайту |
| `--max-age N` | `1` | скільки годин кеш вважається свіжим |
| `--baseline N` | `12` | скільки петицій інших авторів брати в еталон (`0` вимикає) |
| `--baseline-since` | `2026-06-01` | брати в еталон лише петиції, що стартували з цієї дати |
| `--cache` | `data/` | тека кешу |
| `--out` | `reports/` | тека звітів |
| `--template` | вбудований | свій HTML-шаблон з плейсхолдерами `{{…}}` |
| `--font` | `inter` | шрифт звіту: `inter`, `overpass`, `onest`, `golos`, `manrope`, `plex` (усі з кирилицею, Google Fonts) |
| `--no-pdf` | — | не робити PDF |
| `--open` | — | відкрити звіт |

## kmustat — огляд усіх петицій сайту

Окрема команда аналізує **всі** петиції на сайті й збирає 22-сторінковий звіт A4:

| Сторінка | Зміст |
|---|---|
| 1. Загальна картина | петиції та петиції, що набрали 25 000, за роками; розподіл підписів; топ-10 |
| 2. Відповіді і строки | частка відповідей, дні від 25 000 до відповіді, дні збору 25 000, успішність за темами |
| 3. Автори | стать авторів проти статі підписантів, успішність за статтю автора, рекордсмени за створеними петиціями, регіони |
| 4. Підписанти | унікальні люди, частка жінок (загалом, за темами, за роками), КАПС |
| 5. Імена та активність | найчастіші імена й прізвища, години й дні тижня, скільки петицій підписує людина, рекордсмени за підписами |
| 6. Перша доба і модерація | шанс набрати 25 000 залежно від підписів за перші 24 год, криві накопичення успішних петицій, час від створення до публікації |
| 7. Новачки | петиції, з яких люди починають на платформі («магніти»), новачки за місяць і сплески |
| 8. Сигнали аномалій | пік за 10 хв, нічні підписи, нові облікові записи, «разові» люди; вище 95-го перцентиля — виділено |
| 9. Перетин тем | теплова карта «тема → тема», скільки різних тем підписує людина |
| 10. Заголовки і тексти | КАПС, знак оклику, емодзі, довжина — і шанс набрати 25 000; слова успішних заголовків |
| 11. Відповіді уряду | класифікація за ключовими фразами (відмова / підтримка / обіцянка / роз'яснення) з цитатами |
| 12. Сезонність | петиції за місяць, найактивніші місяці, частка жінок за місяць, календарна сезонність |
| 13. Серійні автори | шанс залежно від кількості петицій автора, повтори схожих петицій, однакові заголовки різних авторів |
| 14. Регіони | автори й петиції на 100 тис. жителів (населення — Держстат на 01.01.2022, `petistat/data/population_2022.json`) |
| 15. Не та адреса | петиції, які за компетенцією мали піти Президенту (звання, нагороди, помилування) |
| 16. Хто «розганяє» петиції | частка активних підписантів (10+, 50+ петицій) у першій добі; шанс за годиною й днем публікації |
| 17. Ті, хто підписує разом | координовані групи: пари, що раз у раз підписують ті самі петиції з різницею ≤5 хв (без імен) |
| 18. Автори як підписанти | чи підписує автор свою петицію, взаємна підтримка авторів, «мертві» петиції (<10 підписів) |
| 19. Тексти | мова заголовка, посилання на законопроєкти/постанови, вимоги, що повертаються після відповіді |
| 20. Стать авторів за темами | частка авторок у кожній темі та успіх за статтю автора |
| 21. Медіа і підписи | згадки найбільших петицій і «магнітів» у Google News: скільки статей до / після набору 25 000, джерела |
| 22. Хронологія | підписи по днях збору + дні виходу статей + момент набору 25 000 для 4 найбільш висвітлених петицій |

Рекордсменів (авторів і підписантів) показано у форматі **«Ім'я П.Б.»**: ім'я та ініціали прізвища й по батькові.

```bash
uv run kmustat                 # перший запуск: ~3,5 млн підписів, 10–60 хв залежно від мережі
uv run kmustat --no-signers    # не довантажувати підписантів, рахувати по кешу
uv run kmustat --offline       # лише кеш
uv run kmustat --font overpass   # без --font у терміналі програма запитає шрифт (типово Inter, вибір запам'ятовується)
uv run kmustat --workers 8 --open
uv run kmustat --no-media       # без пошуку згадок у Google News (стор. 21–22 будуть порожні)
```

Підписантів публікує лише нова платформа (з травня 2023 року), тому сторінки 4–9, 16–18 і 12 (частка жінок)
стосуються тільки її. Повний аналіз 3,6 млн підписів займає ~2 хв і ~1 ГБ пам'яті. Кеш стиснутий і лежить у `data/kmu/` (~100 МБ). Завершені петиції завантажуються один раз,
а повторні запуски довантажують тільки активні (ті, кеш яких старший за `--max-age`, типово 24 год).
Перерване завантаження можна просто запустити знову.

### Медіааналіз (стор. 21–22)

Для ~15 петицій (найбільші + «магніти») робимо до трьох коротких запитів у публічний RSS Google News
(`петиція <2 слова> after:<старт−7 дн> before:<завершення+60 дн>`). Слова для запиту — найрідкісніші в назві
(IDF по всіх заголовках сайту). Статтю зараховуємо, якщо в її заголовку є «петиція» + спільне слово з назвою,
або вона ділить з назвою «унікальне» слово (трапляється ≤5 разів на весь сайт). Кеш — `data/kmu/media/`
(знімки, оновлення раз на 7 днів). Обмеження: Google News індексує не всі медіа й не всі старі статті;
«не знайдено» ≠ «медіа мовчали». Соцмережі й Telegram не охоплені.

## План / ідеї на майбутнє

- [ ] **Сайт петицій Президента** (petition.president.gov.ua): парсер і той самий аналіз; порівняння платформ;
      скільки петицій подавали на обидва сайти; чи «геройські» петиції (стор. 15) успішніші за правильною адресою.
- [ ] **Петиції до Верховної Ради** (itd.rada.gov.ua) — аналогічно.
- [ ] **Щоденні знімки за розкладом** (cron / systemd timer): кеш уже зберігає історію — тренди «за тиждень»,
      сповіщення, коли петиція швидко набирає підписи.
- [ ] **Звіт за період:** `kmustat --since 2026-01-01 --until …`, порівняння років.
- [ ] **Інтерактивний дашборд** поруч з A4: фільтри за роком, темою, статтю; пошук петиції.
- [ ] **Строки відповіді за темами** (відповідей поки ~70 — замала вибірка).
- [ ] **Погодинна динаміка перших 48 годин** для 10 найбільших петицій.
- [ ] **Медіа: соцмережі й Telegram** (публічні канали) — перевірити, чи петиції розганяють там, а не в новинах (стор. 21 показує, що медіа здебільшого пишуть уже після 25 000); GDELT для ширшого покриття новин.
- [ ] **Тематичне групування** петицій (ембеддинги / кластеризація) замість схожості за словами заголовка.
- [ ] Географія підписантів — API її не віддає; можливо лише з інших джерел.
- [ ] Тести (pytest) для класифікаторів: стать, КАПС, «не та адреса», відповіді уряду.

### Кеш нічого не видаляє

Кожне завантаження зберігається **окремим знімком з часовою міткою**. Попередні знімки
не перезаписуються й не видаляються, а для роботи береться найсвіжіший. Завдяки цьому
можна відстежувати, як змінювалися підписи з часом.

```
data/index/<UTC-час>.json             список усіх петицій сайту
data/petitions/<id>/<UTC-час>.json    картка петиції разом з автором
data/signatories/<id>/<UTC-час>.json  підписанти
data/sig_<id>.json, all_petitions.json  кеш першої версії (лише читання, використовується як запасний)
```

Назви петицій у звіті не обрізаються. Якщо всі петиції автора не вміщаються на сторінку 1,
скрипт у звіті прямо під час друку ховає нижні рядки (фокусна петиція лишається завжди)
і показує підсумок «…і ще N петицій».

Звіти теж не перезаписуються. `petistat`: `reports/<автор>-<id>/<дата_час>.{html,pdf}`, а `latest.*` — копія останнього.
`kmustat`: архів `reports/kmu-all/<дата_час>.{html,pdf}` і копія з людською назвою
`reports/kmu-all/Петиції до Кабміну — загальний огляд <дата>.pdf` (її й варто пересилати; той самий заголовок у метаданих PDF).
Поруч зберігається технічний `.json` з цифрами — для власної перевірки, у звітах на нього не посилаємося.

## Методика

**Джерело даних.** Публічне API сайту:

- `GET /api/petitions?start=&count=&fields=` — список петицій;
- `GET /api/petitions/:id?include=creator` — картка петиції з автором;
- `GET /api/petitions/:id/signatories` — усі підписанти (ПІБ, ID облікового запису, час підпису).

**Стать.** Визначається за **по батькові**: `-ович`/`-йович` — чоловік, `-івна`/`-ївна` — жінка.
Якщо по батькові немає, запасним варіантом є ім'я. Окремо рахується, скільки людей можна визначити
**лише за прізвищем** (`-ська/-ський`, `-ова/-ов`, `-іна/-ін`). Зазвичай таких лише ~20–25%, бо
прізвища на `-енко`, `-чук`, `-юк`, `-ишин` однакові для обох статей.

**КАПС.** ПІБ вважається записаним КАПСОМ, якщо прізвище, ім'я та по батькові повністю
у верхньому регістрі. Висновок дослідження такий:

- на сайт можна увійти лише через ID.GOV.UA (КЕП, Дія.Підпис, BankID), і ПІБ береться звідти;
  користувач не може його змінити;
- у [специфікації BankID НБУ](https://bank.gov.ua/admin_uploads/article/Specification_BankID_NBU_Bank_v_2.0.2024.05.10.pdf)
  приклад відповіді наведено КАПСОМ (`"lastName": "ГЕРАЩЕНКО"`), а відсутнє по батькові передається як `"n/a"`.
  Таке «n/a» справді трапляється на сайті;
- отже, КАПС вказує на **вхід через банк (BankID) або КЕП, а не через Дія.Підпис**. Чи є в людини
  е-паспорт, з публічних даних визначити неможливо.

**Еталон.** N найбільших петицій інших авторів, що стартували після заданої дати і мають
від 300 до 6000 підписів. Він дає змогу порівняти, наскільки аудиторія автора типова.

## Етика та персональні дані

Списки підписантів публічні на сайті, але це персональні дані. Тому:

- звіт містить **лише агреговані цифри** та найчастіші імена, без ПІБ конкретних людей
  (окрім автора петиції);
- кеш `data/` додано в `.gitignore`, не публікуйте його;
- скрипт робить паузу між запитами, щоб не навантажувати сайт.
