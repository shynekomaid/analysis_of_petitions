# petistat

Інфографіка формату A4 по **підписантах петицій до Кабінету Міністрів України**
([petition.kmu.gov.ua](https://petition.kmu.gov.ua)).

Вставляєте посилання на петицію, і програма:

1. визначає автора петиції;
2. знаходить **усі петиції цього автора** в публічному списку сайту;
3. завантажує підписантів кожної з них, а також еталонну вибірку великих петицій інших авторів;
4. рахує стать підписантів, частку ПІБ, записаних **КАПСОМ**, динаміку підписів і перетини аудиторій;
5. збирає 3-сторінковий звіт A4 у форматах HTML і PDF.

## Що в звіті

| Сторінка | Зміст |
|---|---|
| 1. Огляд | усі петиції автора: підписи, частка жінок, частка КАПСУ; загальні цифри |
| 2. Фокус | вибрана петиція: стать (точно та «лише за прізвищем»), підписи по днях і годинах, прогрес до 25 000, найчастіші імена |
| 3. КАПС | чому частину ПІБ записано великими літерами: докази, порівняння з еталоном, висновок |

## Встановлення

Потрібні Python ≥ 3.10 і (для PDF) Chromium або Google Chrome.

```bash
# з uv (рекомендовано)
uv sync

# або з pip
python -m venv .venv && . .venv/bin/activate
pip install -e .
```

## Запуск

### TUI (інтерактивно)

```bash
uv run petistat          # або просто: petistat (у активованому venv)
```

Програма запитає посилання на петицію (наприклад `https://petition.kmu.gov.ua/petitions/11247`
або просто `11247`) і спитає, чи оновлювати дані, чи робити PDF і яким **шрифтом** верстати звіт.
Потім покаже автора та список його петицій, після підтвердження завантажить дані й відкриє готовий
звіт у браузері. Останнє посилання та вибраний шрифт вона запам'ятовує (`data/state.json`).

### Одною командою

```bash
uv run petistat https://petition.kmu.gov.ua/petitions/11247
uv run petistat 11247 --open             # відкрити звіт після генерації
uv run petistat 11247 --refresh          # примусово оновити дані автора
uv run petistat 11247 --offline          # лише кеш, без мережі
uv run petistat 11247 --no-pdf           # тільки HTML
uv run petistat 11247 --baseline 20 --baseline-since 2026-01-01
python -m petistat 11247                 # те саме без entry point
```

| Опція | Типово | Опис |
|---|---|---|
| `--refresh` | — | ігнорувати свіжість кешу для даних автора |
| `--offline` | — | не звертатися до сайту |
| `--max-age N` | `1` | скільки годин кеш вважається свіжим |
| `--baseline N` | `12` | скільки петицій інших авторів брати в еталон (`0` вимикає) |
| `--baseline-since` | `2026-06-01` | брати в еталон лише петиції, що стартували з цієї дати |
| `--cache` | `data/` | тека кешу |
| `--out` | `reports/` | тека звітів |
| `--template` | вбудований | свій HTML-шаблон з плейсхолдерами `{{…}}` |
| `--font` | `inter` | шрифт звіту: `inter`, `overpass`, `onest`, `golos`, `manrope`, `plex` (усі з кирилицею, Google Fonts) |
| `--no-pdf` | — | не робити PDF |
| `--open` | — | відкрити звіт |

## Де що лежить

```
petistat/
  api.py              клієнт API + кеш зі знімками
  analysis.py         класифікація (стать, КАПС) і метрики
  render.py           HTML/SVG-рендер, PDF через headless Chromium
  cli.py              TUI (rich) та CLI
  templates/report.html  шаблон A4
data/                 кеш (у .gitignore)
reports/              звіти (у .gitignore)
legacy/               перша версія: одноразовий скрипт regen.py
```

### Кеш нічого не видаляє

Кожне завантаження зберігається **окремим знімком з часовою міткою**. Попередні знімки
не перезаписуються й не видаляються, а для роботи береться найсвіжіший. Завдяки цьому
можна відстежувати, як змінювалися підписи з часом.

```
data/index/<UTC-час>.json             список усіх петицій сайту
data/petitions/<id>/<UTC-час>.json    картка петиції разом з автором
data/signatories/<id>/<UTC-час>.json  підписанти
data/sig_<id>.json, all_petitions.json  кеш першої версії (лише читання, використовується як запасний)
```

Назви петицій у звіті не обрізаються. Якщо всі петиції автора не вміщаються на сторінку 1,
скрипт у звіті прямо під час друку ховає нижні рядки (фокусна петиція лишається завжди)
і показує підсумок «…і ще N петицій».

Звіти теж не перезаписуються: `reports/<автор>-<id>/<дата_час>.{html,pdf,json}`, а `latest.*`
завжди вказує на останній.

## Методика

**Джерело даних.** Публічне API сайту:

- `GET /api/petitions?start=&count=&fields=` — список петицій;
- `GET /api/petitions/:id?include=creator` — картка петиції з автором;
- `GET /api/petitions/:id/signatories` — усі підписанти (ПІБ, ID облікового запису, час підпису).

**Стать.** Визначається за **по батькові**: `-ович`/`-йович` — чоловік, `-івна`/`-ївна` — жінка.
Якщо по батькові немає, запасним варіантом є ім'я. Окремо рахується, скільки людей можна визначити
**лише за прізвищем** (`-ська/-ський`, `-ова/-ов`, `-іна/-ін`). Зазвичай таких лише ~20–25%, бо
прізвища на `-енко`, `-чук`, `-юк`, `-ишин` однакові для обох статей.

**КАПС.** ПІБ вважається записаним КАПСОМ, якщо прізвище, ім'я та по батькові повністю
у верхньому регістрі. Висновок дослідження такий:

- на сайт можна увійти лише через ID.GOV.UA (КЕП, Дія.Підпис, BankID), і ПІБ береться звідти;
  користувач не може його змінити;
- у [специфікації BankID НБУ](https://bank.gov.ua/admin_uploads/article/Specification_BankID_NBU_Bank_v_2.0.2024.05.10.pdf)
  приклад відповіді наведено КАПСОМ (`"lastName": "ГЕРАЩЕНКО"`), а відсутнє по батькові передається як `"n/a"`.
  Таке «n/a» справді трапляється на сайті;
- отже, КАПС вказує на **вхід через банк (BankID) або КЕП, а не через Дія.Підпис**. Чи є в людини
  е-паспорт, з публічних даних визначити неможливо.

**Еталон.** N найбільших петицій інших авторів, що стартували після заданої дати і мають
від 300 до 6000 підписів. Він дає змогу порівняти, наскільки аудиторія автора типова.

## Етика та персональні дані

Списки підписантів публічні на сайті, але це персональні дані. Тому:

- звіт містить **лише агреговані цифри** та найчастіші імена, без ПІБ конкретних людей
  (окрім автора петиції);
- кеш `data/` додано в `.gitignore`, не публікуйте його;
- скрипт робить паузу між запитами, щоб не навантажувати сайт.
